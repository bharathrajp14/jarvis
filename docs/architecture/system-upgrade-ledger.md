# BR JARVIS SYSTEM UPGRADE LEDGER & CHANGE CONTROL

This ledger records every architectural modification across the codebase with rationale, dependencies, risk assessment, and verification criteria.

| Change ID | Subsystem | Target File(s) | Prior Behavior | New Behavior | Rationale / Requirement | Risk | Verification Test |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **UPG-01** | **Version Authority** | `core/version.py`, `pyproject.toml`, `setup.py`, `start.py`, `api/server.py`, `web/app.js` | Version scattered across `38.5.0`, `40.2.0`, and hardcoded strings. | Single canonical version module `core/version.py` (`40.2.0`) feeding all clients, APIs, banners, and metadata. | Requirement 7: Single source of version truth. | Low | `tests/unit/test_core_runtime.py` |
| **UPG-02** | **Configuration & Environment** | `core/config.py`, `core/bootstrap.py` | Business modules reading raw `os.environ.get()` with conflicting fallbacks. | Strongly typed `JarvisConfig` with explicit precedence: Defaults → `config/models.json` / `api_keys.json` → `.env` → Environment → Overrides. | Requirement 6: Strongly typed configuration authority. | Med | `tests/unit/test_config.py` |
| **UPG-03** | **WebSocket & Authentication** | `api/routes/auth.py`, `api/routes/websocket.py`, `api/server.py`, `web/app.js` | Web client looping on 401 when `SERVER_API_KEY` was configured; long-lived tokens in query parameters. | Session-based auth: REST login/ticket issuance with short-lived TTL; secure WS handshake; proper 401 handling in UI; origin validation; typed event envelope. | Requirement 10, 11, 12, 13: Secure WebSocket protocol & authentication. | Med | `tests/integration/test_websocket_auth.py` |
| **UPG-04** | **Observability & Logging** | `api/server.py`, `core/logging.py` | `sys.stdout` was monkey-patched globally with `WSBroadcastStream` interceptor. | Standard logging handlers (`WSLogHandler`) attached cleanly to application logger without replacing `sys.stdout`. Redaction of secrets. | Requirement 34, 35: Remove global stdout hacks; structured logging. | Med | `tests/unit/test_logging.py` |
| **UPG-05** | **CLI Modes & Commands** | `core/cli.py` | `/mode` printed text but did not change agent profile, model policy, or orchestrator mode. | `/mode <name>` updates active `AgentProfile`, orchestrator mode, and routes dynamically with feedback. | Requirement 19, 20: Real CLI mode switching and real backend actions. | Low | `tests/cli/test_cli_modes.py` |
| **UPG-06** | **Tool Execution & Registry** | `tools/registry.py`, `tools/tool_runtime.py` | `execute_tool` returned raw strings or unstandardized dicts with ad-hoc error formats. | Unified `ToolResult` dataclass with status, execution time, error codes, and verification evidence. | Requirement 29, 30, 31: Canonical tool registry and execution contract. | Med | `tests/unit/test_tool_runtime.py` |
| **UPG-07** | **Web UI Client Reliability** | `web/app.js`, `web/index.html`, `web/style.css` | 401 connection loops, UI out-of-sync with backend task states, unsafe DOM insertions. | Reliable state machine (Connecting, Ready, Thinking, Planning, Executing, Verifying, Completed), sanitized HTML, reconnect backoff, artifact downloads. | Requirement 8, 9, 45, 46: Reliable web UI client. | Med | `tests/ui/test_web_ui.py` |
| **UPG-08** | **Launchers & Startup Consolidation** | `start.py`, `server.py`, `dashboard/server.py` | Competing boot sequences across `start.py`, `server.py`, and `dashboard/server.py`. | Single canonical startup sequence delegating through `CoreBootstrapper` and `api/server.py`. Deprecated isolated `dashboard/server.py`. | Requirement 4, 5, 14: Canonical startup architecture. | Med | `tests/unit/test_server_web.py` |
